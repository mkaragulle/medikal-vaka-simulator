KlinikIQ V373 Deep Smoothness / Cursor Polish Summary

Changed files:
- src/components/PremiumCursor.jsx
- src/components/KlinikIQCustomScrollbars.jsx
- src/components/PerformanceOptimizer.jsx
- src/App.jsx
- src/index.css

1) Custom cursor polish
- Removed unused scrollbar hit-test helper logic from PremiumCursor.
- Simplified the runtime cursor CSS so it no longer depends on a broad `body *` cursor rule or scrollbar pseudo selector matching.
- Added short cursor suspension during scroll and resize. While the browser is busy scrolling/resizing, the cursor stops doing transform updates and fades out briefly, then resumes smoothly.
- Theme MutationObserver now watches only `data-theme`, not every `class` change. This prevents scroll/performance classes from triggering cursor theme recalculation.
- Cursor remains premium, custom, visible in normal interaction, and hidden in text-input contexts as before.

2) Custom scrollbar optimization
- Reduced maximum tracked custom scrollbar containers from 32 to 24.
- Removed duplicate global window scroll update path; the window scrollbar entry already listens to window scroll.
- Added minimum scan interval and safer delayed scan scheduling to avoid repeated full DOM rescans during rapid UI changes.
- MutationObserver now only schedules a scan when relevant scroll/top-layer nodes are added/removed or when a scrollable parent is affected; it no longer treats every childList mutation as a full-rescan trigger.
- Theme observer now watches only `data-theme`, not class changes.

3) Interaction smoothness governor
- PerformanceOptimizer now marks short `ki-route-transitioning` windows on meaningful UI interactions such as buttons, cards, options, modals and dropdowns.
- During those short windows, CSS temporarily reduces expensive transition/animation/blur cost so clicks, popups and route changes feel more immediate.

4) Lazy screen preloading
- Added idle preloading for heavy lazy screens after login: CasePlayer, TusPearlStudyScreen, StudyReviewHub, KomiteModeWorkspace, ExamResults and AIGeneratedQuestionView.
- This keeps initial load protected but reduces the “first time opening this screen is slow” feeling after the app has been idle.

5) CSS smoothness correction
- Removed broad `ki-is-scrolling *` / `ki-is-resizing *` rules and replaced them with targeted selectors.
- Removed broad permanent `translateZ(0)` layer promotion from large card groups.
- Removed `content-visibility:auto` from highly visible/interactive route shells and branch cards where it could feel like delayed loading.
- Kept content-visibility only on long list rows where it helps offscreen rendering.
- Preserved dark mode, premium visual language, hover states and existing layout.

Validation performed in sandbox:
- Syntax check passed for non-JSX runtime files changed: PremiumCursor.jsx, KlinikIQCustomScrollbars.jsx, PerformanceOptimizer.jsx.

Expected user-visible improvement:
- Less mouse stutter from the custom cursor.
- Smoother scroll and page navigation.
- Faster-feeling popup/dropdown/card interactions.
- Less “late opening” on lazy-loaded screens after the app has been idle.
- Lower risk of global DOM scan spikes while navigating around the interface.
