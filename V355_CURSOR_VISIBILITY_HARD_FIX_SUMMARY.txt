V355_CURSOR_VISIBILITY_HARD_FIX_SUMMARY

Problem:
- V354 cursor was too dependent on pointer media detection and class-based CSS.
- Old cursor cleanup/reset CSS could still interfere with the new cursor layer in some browser/cache states.
- Result: native cursor could be hidden while the custom cursor was not reliably visible.

Fix:
- PremiumCursor.jsx was rebuilt again with a new isolated DOM root: data-ki-pointer-v355-root="true".
- The new cursor does not use old class names such as premium-cursor, ki-cursor, cursor-ring, cursor-lens, or ki-simple-cursor-root.
- The cursor is rendered as an inline SVG circle + dot, not as a background/glass div.
- The component no longer exits early based on pointer media-query detection; it activates on the first real mouse/pointer movement.
- Both pointermove and mousemove are listened to directly, improving reliability on browsers where PointerEvent behavior is inconsistent.
- Native cursor is hidden only after the custom cursor has been activated.
- Text inputs keep the normal text cursor.
- Old cursor roots/styles/classes are removed at runtime.
- A final V355 CSS safety block was appended to index.css.

Expected result:
- The cursor should now visibly appear as a minimal teal ring + dot.
- No square box, glass layer, backdrop blur, glow block, or old lens artifact should remain.
