KlinikIQ V372 Performance / Smoothness Changes

Changed files:
- src/components/PremiumCursor.jsx
- src/components/KlinikIQCustomScrollbars.jsx
- src/components/CaseList.jsx
- src/components/DiagnosisQuiz.jsx
- src/services/localBackend.js
- src/index.css

Main changes:
1. PremiumCursor.jsx
- Replaced the interpolated cursor-follow RAF loop with a direct one-frame transform update.
- Cursor no longer keeps animating after movement settles.
- Cursor position now follows the physical mouse more immediately.
- Target mode detection is still preserved but batched into the same animation frame.
- Custom cursor design, text input behavior and interactive states are preserved.

2. KlinikIQCustomScrollbars.jsx
- Reduced max tracked scrollbar targets from 72 to 32.
- Removed global pointermove activity tracking from the custom scrollbar layer.
- Removed pointermove listener from each scrollbar track; pointerenter and drag still work.
- Replaced broad body-wide scroll-container scanning with targeted candidate selectors.
- MutationObserver now watches childList changes instead of all class/style attribute changes across the whole body.
- Theme detection is cached instead of recalculated on every scrollbar update.
- Top-layer occlusion cache duration increased to reduce repeated layout measurement.
- Custom scrollbar appearance and drag behavior are preserved.

3. CaseList.jsx
- Removed GlossaryText from dense case navigation cards.
- Case list titles are now plain text for faster scrolling and branch navigation.
- Added memoized CaseListItem rows.
- Simplified horizontal reset key calculation to avoid long per-case string joins.
- Case selection behavior and solved/open state indicators are preserved.

4. DiagnosisQuiz.jsx
- Answer submission now uses React startTransition so heavy feedback rendering is lower priority.
- Option selection remains immediate.
- Correct/wrong feedback behavior is preserved.

5. localBackend.js
- Added in-memory cache for localBackend reads/writes.
- localStorage writes are now batched and flushed during idle time.
- Pagehide/beforeunload/visibilitychange flushes protect against data loss.
- This reduces synchronous storage blocking after answer selection, stats updates and history saves.

6. index.css
- Added deeper V372 scroll and list smoothness guardrails.
- Added contain/content-visibility rules for repeated cards and dense list rows.
- Scroll/route transition states now reduce heavy shadows, filters, backdrop filters, transforms and animations.
- Continuous decorative animations are paused by default in performance mode and resume on hover/launch where appropriate.
- Premium visual identity is preserved, but idle CPU/GPU cost is lower.

Validation notes:
- Patched files were checked with TypeScript parser settings for JSX/JS syntax where practical.
- Full npm install/build could not be completed in the sandbox because dependency installation timed out.
- Run locally: npm install && npm run build.

Expected result:
- Cursor should feel less delayed.
- UI navigation should feel lighter.
- Case list and catalog list scrolling should be smoother.
- Answer submission should feel less blocking.
- Popups/dropdowns should open with less main-thread contention.
