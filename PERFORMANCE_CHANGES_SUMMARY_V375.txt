KlinikIQ V375 — Diğer Olgular Scrollbar Fast Refresh

Changed files:
- src/components/CaseList.jsx
- src/components/KlinikIQCustomScrollbars.jsx

What changed:
1. CaseList.jsx
   - Horizontal case lists now receive explicit scroll metadata:
     data-scroll-container="true"
     data-scrollable="true"
     data-ki-scroll-priority="other-cases"
   - The horizontal list dispatches `klinikiq:scrollbars-refresh` immediately after mount.
   - A second refresh is dispatched in the next requestAnimationFrame after layout settles.
   - A short 80 ms settle refresh is dispatched to catch late card width/layout changes.
   - This only applies to horizontal lists, especially the “Diğer olgular” browser.

2. KlinikIQCustomScrollbars.jsx
   - Added a dedicated `SCROLLBAR_REFRESH_EVENT` listener.
   - Added priority candidate discovery for `[data-ki-scroll-priority]`, `.bottom-case-browser .horizontal-case-list`, and horizontal lists marked as scrollable.
   - Explicit refresh now clears the pending delayed scan, resets top-layer cache, scans immediately, and follows with two short settle scans.
   - MutationObserver attribute matching now recognizes priority/horizontal scroll containers.

Preserved behavior:
- Custom scrollbar was not removed.
- Custom cursor was not removed.
- Glossary behavior was not changed.
- TUS/KOMİTE flows were not changed.
- Medical cases, answers, feedback, glossary content and scientific data were not changed.
- Existing V374 performance optimizations were preserved.

Build test:
- `npm run build` completed successfully.
- Vite large chunk warnings remain expected because case/glossary data were not shortened or removed.

GitHub safety:
- Final zip excludes node_modules, dist, .git, cache, logs and nested zip files.
