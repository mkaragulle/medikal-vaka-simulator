KlinikIQ V375 - Diğer Olgular Scrollbar Fast Refresh Patch

Changed files:
1. src/components/CaseList.jsx
   - Added a lightweight refresh signal for horizontal case lists.
   - When the "Diğer olgular" horizontal list mounts or its visible case set changes, it now dispatches `klinikiq:scrollbars:refresh`.
   - The signal is sent once immediately after layout and once shortly after layout settles, so the custom scrollbar can appear without waiting for the generic MutationObserver debounce.
   - Added `data-scroll-container="true"` and `data-scrollable="true"` only for horizontal lists to make the target explicit for the custom scrollbar scanner.
   - Existing 48-card/list behavior, solved state, selected state, title rendering, and case data were not changed.

2. src/components/KlinikIQCustomScrollbars.jsx
   - Added a listener for the targeted `klinikiq:scrollbars:refresh` event.
   - The listener performs an immediate scan plus a short follow-up scan for layout-settling cases.
   - Existing custom scrollbar design, z-index behavior, drag behavior, top-layer occlusion checks, debounce logic, and V374 optimizations were preserved.

Preserved intentionally:
- Medical/TUS cases and answers were not edited.
- Glossary content and glossary tooltip behavior were not removed.
- Custom cursor was not removed.
- Custom scrollbar was not replaced by native scrollbar.
- Dark/light theme styling was not changed.
- No heavy refactor was introduced.
- No node_modules, dist, cache, .git, .vite, .vercel, or nested zip is included in the final package.

Expected effect:
- The custom scrollbar in the "Diğer olgular" horizontal browser should appear much faster after opening a case, changing branch filters, or searching within other cases.
- General page performance should remain the same because this refresh is scoped to horizontal case-list lifecycle changes.
